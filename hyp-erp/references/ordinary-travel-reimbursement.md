# 普通差旅报销

入口：`My HYP → 我的财务 → 普通差旅报销`，图片线索 `/images/process/3.jpg`。本次已确认由部门口径承担的出差使用；内部制度以用户及公司要求为准。先读 [共用操作](form-common.md)。

2026-09-08 已在实际 ERP 临时表单核验日期日历、差旅费用行、自动部门分拆及修改、空分拆时新增部门、电子普通发票登记、个人收款行及附件窗口，最后取消表单，未提交审批。

## 1. 行程证据与主表

核对标题“普通差旅报销”，费用分拆表头应是 **部门、费用、进项税、成本**。没有普通日常的“报销费用类型”，也没有需要选择的项目和订单。

出差起止依据实际往返乘行日期及相关行程记录，不用开票或收件日期代替。仅单程、日期冲突或住宿日期不明且必须填写时补问。整理费用分类、金额和业务目的；不能仅凭项目暂未找到就推定由部门承担。

填写主题、归属公司、出差开始日期、出差结束日期、报销事由，核对起草人、报销人、报销所在部门及货币，保留系统申请时间。主题可用“报销人＋日期范围＋目的地＋普通差旅报销”；事由写日期、地点、已确认工作目的及费用范围。公司与姓名不使用示例作者信息。

### 日期日历

点对应日期的“显示日期选择框”，核对年份，用月份按钮选月份，再点击当月可用日期。灰色前后月日期不当本月日期。无 ref 时从当前 DOM 的文字、状态和边界定位再原生点击，不固化坐标，不向掩码框批量填 ISO 字符串。核对两处完整年月日后再新增行程。

## 2. 差旅费用清单

点击 **差旅报销费用清单** 的“新增”，打开“新增差旅报销信息”。起止日期继承主表，天数和小计由系统计算。

填出发地、目的地和当前行费用。实测字段：机票、车船费、市内交通费、托运费、住宿费、自驾车费、出差补助、工作餐费、摘要。飞机归机票，铁路等归车船费，打车归市内交通费，酒店归住宿费，已确认出差工作餐归工作餐费；保险等未单列项目先核对归类口径。无依据不生成补助或其他费用。

同次行程可按实际类别汇总，每项金额保留票据追溯；跨阶段或路线需要时分行。核对小计后点**新增差旅报销信息的确定**，确认主表金额、行程行和分拆区域状态。

## 3. 先检查自动部门分拆，再决定修改或新增

**实测新增第一条差旅费用后，系统自动把全部金额分配到主表报销所在部门。** 普通票也要核对归属，不能因没有专票就略过。

- 已有自动分拆行：选中“费用分拆”的具体部门行，点该区域 **修改**，打开“修改报销部门”。按本次口径核对或更换部门，在这里登记电子发票，不再无条件点新增。
- 没有分拆行且有待分配金额：点分拆“新增”，打开“新增报销部门”。已实测空分拆新增时，部门按钮为“选择值”，费用预填待分配金额。
- 多部门承担：先按用户给出的金额调整现有行，再为剩余金额新增部门；费用及票据分配可追溯，不重复全额登记。多部门实际业务分配尚未用真实任务验证，按当前表单及本次口径核对。

自动分配已占满时，点新增实测提示 **“报销金额必须大于0才能添加部门”**，即使主表金额为正。先查分拆是否已分完，不改大费用或反复点新增。空白主表也曾提示“没有填写报销人或者报销金额”，应先填实际行程费用。

### 新增/修改报销部门

子表字段：部门按钮、费用、只读剩余费用、进项税、只读成本、是否有电子发票。

1. 部门按钮显示已选名称或“选择值”，按 [部门级联菜单](form-common.md#部门级联菜单) 操作。自动回填须与本次承担口径核对，不查项目和订单。
2. 费用填本部门实际承担金额。“剩余费用”反映当前填写后的余额：实测新建时当前费用已预填全额，剩余为 0；不能看到 0 就把本行费用清零。
3. 电子普通发票也选“有”，从右侧“发票信息(进项税与电子发票) → 新建”按 [登记步骤](form-common.md#电子发票登记与进项税) 逐张填票种、金额、票号和数量。
4. 核对进项税、成本、发票和分配金额，点**报销部门子表的确定**。普通电子发票实测进项税为零，成本等于费用。
5. 回主表核对 `部门费用合计＝差旅行小计合计＝主表报销金额`。后续改行程金额、删费用或改报销所在部门，重新检查分拆及收款，不假定全部自动同步。

“删除所有”实测会直接清空所在区域；真实报销优先修改准确行，不用清空全部来解决普通的剩余额度问题。

## 4. 收款、附件与交接

主表 **收款信息 → 新增**，按 [收款操作](form-common.md#收款信息) 选择真实记录、核对银行回填、填实付与冲账并确定，核对收款合计。

主表 **上传附件 → 请上传附件**，按 [附件操作](form-common.md#附件) 上传原件及必要行程证明，核对文件与进度后确认加入主表。

最后核对日期、地点、用途、差旅费用、部门分拆、发票登记、收款和附件。依 [交接要求](form-common.md#完成与交接) 保存稳定个人资料，保留正式任务表单，由用户本人检查提交。
