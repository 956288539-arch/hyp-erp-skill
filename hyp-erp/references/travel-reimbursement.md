# 项目差旅报销

适用入口：BrowserOS Neo → 霍普 ERP → `my hyp → 我的财务 → 项目差旅报销`。

菜单、固定公司、收款人与用户提交要求来自用户说明。2026-09-07 已实测进入主表、通过日历选日期、添加费用清单及收款信息，并查看项目分拆控件；项目归属与附件上传仍需随实际任务核验。

## 页面入口

登录后的左侧 `My HYP → 我的财务` 打开 `#my_financial`。在顶部业务按钮中选择“项目差旅报销”，弹出同名报销表单。

顶部按钮是图片按钮，可访问性快照中可能只有匿名 button。应通过当前截图与 DOM 中图片核对再操作；此次“项目差旅报销”按钮的图片为 `/images/process/4.jpg`。动态 DOM ID 和快照 ref 只适用于当时的页面，不固化到后续任务。

## 1. 整理票据证据

每个用户指定文件夹代表一次完整出差。先列出文件与数量，把其中票据和辅助证明关联起来，不混入同级其他出差文件夹。读取用户为本次任务提供的文件，PDF、图片和表格分别采用相应可用工具。遇到扫描票据或识别不清的金额、日期、票号时，查看原页面确认。

为本次任务建立明细账，至少包含：来源文件及页码、票据类型、票据号码（如有）、实际乘行或住宿日期、开票日期、路线或酒店、费用类别、含税金额、明确列出的不含税金额与税额、是否专票、拟报销金额及疑点。计算使用十进制或整数分，金额保留两位小数。

- 区分发票、机票或火车票、行程单、订单与付款证明。同一费用的多个证明关联到同一明细，避免重复计入。
- 核对发票号码等唯一信息识别重复件；相同金额本身不能证明重复。
- 发票明细含折扣负数行时，核对折扣后的价税合计，不把优惠前金额或负数行当成另一笔独立报销。酒店同日同价但票号不同的两张发票分别保留；不能仅凭金额相同删除其中一张。
- 往返机票、动车票、酒店发票、打车发票、餐饮发票分别归类。退改签、退款、个人消费或其他费用有明确证据时单列，不能自行判定全部可报销。
- 金额不清、票据冲突、缺失回程等问题列为待核实项。已确认的金额与未确认的金额分开呈现。
- 发票可以证明费用，通常不能独立证明具体项目或商务目的。项目名称与出差目的以用户说明或明确的业务资料为准。
- 核对购买方抬头与指定归属公司。若二者不同，说明具体差异并询问本次归属口径，保留用户原先指定值，不根据发票擅自改公司。用户确认后按确认口径填写。

填表前给用户一份简短摘要：行程、各类费用与拟报销总额，以及待补信息。没有实质疑点时继续已授权的填写工作。

## 2. 确定行程与主表内容

出差日期优先依据往返飞机的实际乘行日期，而不是机票开具日期。动车等其他行程凭证用于补充核对；全程铁路出行时可据实际乘车日期确定。跨日到达时按行程确认返程结束日期。仅有单程票或日期互相矛盾时询问用户，不自行补造完整行程。

代订机票普通发票的备注可能包含实际乘行日期、路线、航班号和乘机人，可据此核对行程。酒店发票只有开票日期时，不能把它当作入住日期，也不能从两张发票推定住了两晚；只有表单需要这些住宿细节时再补充询问。

| 主表内容 | 填写方法 |
| --- | --- |
| 主题名称 | 保留已有准确标题；空白或无意义的默认标题改为简洁明确的标题。推荐 `马腾宇＋实际日期范围＋目的地＋项目差旅报销`，项目已知时可加入项目简称。 |
| 归属公司 | 选择完整匹配的 `上海霍普建筑规划设计有限公司`，并核对实际选中结果。 |
| 报销所在部门 | 查看当前系统值；用户未指定时保留，不为寻找项目随意改为其他部门。 |
| 出差日期 | 填入经行程证据支持的起止日期，核对日期控件显示值。 |
| 报销事由 | 用已证实的信息说明日期、地点、项目或出差目的及费用范围。项目与目的尚未知时，可先填写事实部分并集中询问。 |
| 项目等其他必填项 | 根据用户提供的信息或 ERP 中可以唯一确认的记录选择。无法唯一确定时询问。 |

报销事由可采用如下结构，仅填入有依据的内容：

`本次于【起止日期】赴【地点】开展【已确认的项目/工作事项】，申请报销本次差旅发生的【实际费用类别】，合计人民币【拟报销金额】元。`

这是写作结构，不能把括号占位内容原样留在已完成表单中。没有依据的事项应省去或作为待补问题。

### 日期控件

本表的日期框为 SmartClient 格式化控件，直接批量填入 `YYYY-MM-DD` 曾产生缺失年份的错误显示。使用旁边的“显示日期选择框”：核对年份，点击月份按钮选择月份，再点击日期。月份、日期单元格可能没有 ref，此时按当前 DOM 单元格的文字与边界定位，再通过原生鼠标操作点击。核对输入框最终完整显示正确日期。主表日期确认后再新增费用行，子表会继承起止日期并自动计算出差天数。

## 3. 填写右侧差旅报销费用清单

点击“差旅报销费用清单”区域的“新增”，打开“新增差旅报销信息”。该子表按行程填写，可将同次出差的费用按类别汇总为一行；每个汇总金额保留对应票据的追溯关系。

实测字段：开始日期、结束日期、出发地、目的地、天数、机票、车船费、市内交通费、托运费、住宿费、自驾车费、出差补助、工作餐费、小计、摘要。天数和小计由系统计算。返程途经其他城市时在摘要中写明。

| 票据类别 | 填写方向 |
| --- | --- |
| 往返飞机票 | “机票”，核对往返日期、路线与金额。 |
| 动车/火车票 | “车船费”，具体票种依当前页面说明。 |
| 酒店发票 | “住宿费”。发票张数不等同于住宿天数。 |
| 打车发票 | “市内交通费”，关联行程单，防止重复计费。 |
| 餐饮发票 | 出差工作餐填“工作餐费”；用途不明确时询问。 |

优先使用实际字段标签、可见文本、表头和行上下文定位；跨 iframe 时按 BrowserOS Neo 当前工具支持的接口操作。采用 snapshot → act → 验证循环，普通文本与金额字段使用批量填写，日期按上述日历方式处理。信任操作返回的页面差异，在需要新 ref 时重新取快照；每次弹窗、增行或页签切换后不沿用过期定位。小计正确后点击子表“确定”，核对主表报销金额已随费用行汇总。

交通、住宿、餐饮等实际发生金额不自动产生出差补贴。没有证据的费用项采用页面允许的空白或零值，不能填造费用。

## 4. 项目费用归属与专票进项税

“费用分拆”区域同时承载项目归属。该区域的“新增”打开“新增项目”，字段包括项目、订单编号、业务部门、费用、剩余费用、进项税、成本、是否有电子发票。选择实际项目后，核对系统带出的订单编号与业务部门。“费用”默认为未分配的报销金额；多项目时按用户明确给出的分配口径填写，并核对剩余费用。

项目输入框的下拉选项可能是有限的可选项目集合，输入名称不等于已选中项目。必须匹配实际下拉记录，并核对订单编号已经回填。目标项目不在列表时说明具体情况，请用户选择或提供可识别的项目；不能仅凭同城市选择另一项目。用户接手查找时保持页面，不同时进行会改变页面状态的操作。

标题“如有增值税专用发票，进项税必填，其他发票无需填写”针对进项税填写。普通发票仍按项目归属分配费用，进项税保留零值，成本与费用一致。“是否有电子发票”是单独字段，电子普通发票也属于电子发票，不能因为没有专票而选“无”。

发现专票时继续以下步骤：

1. 识别发票明确注明的票种，包括明确标识专用发票的电子发票；电子格式本身不能证明是专票。
2. 从发票读取不含税金额、税额和价税合计。税率仅在发票有明确标注且页面需要时照录，不根据常识套用税率或擅自计算抵扣额。
3. 保持分拆与原发票、费用清单行的关联。多张专票分别保留明细；页面要求合并时，也保留每张票据金额的计算依据。
4. 核对 `不含税金额＋税额＝价税合计`。ERP 中“费用”为分配的含税费用，“进项税”按符合本次口径的专票税额填写，核对自动计算的“成本＝费用－进项税”。注意部分报销与页面汇总口径。
5. 分拆表示同一费用的组成，不能把含税金额和其税额再次相加计入报销总额。填后核对 ERP 的实际汇总结果。
6. 抵扣资格、税务分类或 ERP 分拆口径如需额外业务判断且资料不足，保留已知数据并询问用户。普通票按页面实际要求处理。

## 5. 收款信息与附件

- 在“收款信息”区域点击“新增”，选择“个人”，填写并匹配收款方 `马腾宇`，核对系统回填的银行信息。填写付款金额；无冲账时冲账金额采用零值或系统允许的空白。点击子表“确定”加入收款行。
- 银行和账号使用 ERP 既有记录或用户本次明确提供的信息。缺失必填信息时询问；不将完整账号写入 skill、版本记录或完成摘要。
- 若存在收款金额字段，填入经核对的本次应收报销金额。有借款冲抵、分次收款等已有情况时先确认对应口径，不覆盖为默认总额。
- 在用户委托用所提供票据办理本次 ERP 报销的范围内，通过页面提供的上传入口附上相应票据和所需证明；使用 BrowserOS Neo 的 upload 操作，将本地文件路径设置到实际文件输入控件。
- 验证附件名称、数量与上传状态，同一行程单和发票可同时作为证明附件，但只能计一次对应费用。

## 6. 核对并交给用户

完成后检查：

- 主题、公司、日期、事由与已确认行程一致。
- 费用清单各行、各类别汇总与票据明细账一致，专票分拆既未遗漏也未重复计入。
- 拟报销金额、ERP 报销合计与收款金额口径一致；明确列出冲抵等差异。
- 收款人为马腾宇，附件显示上传成功，已知必填项已完成。

当前实测主表底部只有“提交”和“取消”，未发现独立的草稿保存入口。子表“确定”把行加入当前表单，不代表主表已保存到服务器。保留页面并明确告知尚未提交；不要刷新、关闭或通过新开同一 URL 来恢复这张未提交表单。金额冲突或必填项缺失时，将状态报告为“部分填好，待补”，而不是“可以提交”。如果之后页面提供草稿功能，先核实其行为再更新流程。

最后给出简短交接：主题、出差日期、报销总额、收款人、专票分拆与附件状态、尚需用户处理的内容，以及“请你在当前 BrowserOS Neo 页面检查并提交”。保留该任务标签页供用户接手。停止在提交之前，不以“提交”或“发起审批”来测试表单校验，也不把用户核对金额或补充信息视为委托代点提交。
