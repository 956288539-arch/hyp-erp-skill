# 项目日常、普通日常与普通差旅

先完成 [本次类型选择](reimbursement-types.md) 与 [用户资料核对](user-profile.md)。2026-09-07 已实际查看这些入口与主表、两种日常报销的明细子表及相关选项；尚未用真实票据验证这三类的完整填写。按当前页面操作并核对，不用“提交”测试字段校验。

## 日常报销共用流程

项目日常与普通日常主表均有主题、起草人、报销人、报销所在部门、归属公司、报销时间、报销金额、货币种类、备注、附件及收款信息。普通日常另有“报销费用类型”。没有差旅表单的出差起止日期；日常事项的实际发生日期写入有依据的摘要或备注，保留系统报销申请时间，不伪造出差行程。

1. 按本次资料填写主表。主题可用“报销人＋事项日期＋项目或事项简称＋日常报销”；备注说明用途、承担项目或部门及实际费用范围。仅保留有依据的信息。
2. 使用相应“日常报销费用清单”旁的“新增”，进入“新增报销信息”。不要在标有“报销科目合并，本框内不再需要填写数据”的旧汇总区域录入。
3. 按实际用途选择“报销科目”，再查看对应“报销选项”。项目日常已看到业务招待费、市内交通费、办公费、制作费等科目；选项随科目及权限变化。请甲方吃饭可在用户已确认业务招待用途时选匹配的业务招待科目，不能仅看到餐饮发票就自行定为业务招待。
4. 填写当前行费用和摘要；摘要按已有信息记录发生日期、工作事由及必要的关联信息。科目或选项含义不明时查看页面说明并补问，不默认选择第一项。
5. 按下节区分项目或部门归属。有专票时根据发票及适用口径填写进项税；普通发票不自行产生抵扣。已见“代扣偶然所得税金”字段，不能对普通餐费等随意赋税率，也不自行覆盖系统计算。
6. 确认当前明细里的“是否有电子发票”。有电子普通发票时照实际出现的发票登记区域填票种、价税合计、票号、数量，逐张防重复；具体窗口以本次页面为准。参照 [项目差旅的发票登记与金额核对](travel-reimbursement.md)，不要照抄其项目分拆结构。
7. 子表“确定”后核对费用明细、成本与主表总额。不同科目或不同承担项目、部门分别列行；同一消费的原件与行程、消费记录只计一次费用。

### 项目日常的项目归属

明细字段已见项目、订单编号、业务部门、费用、进项税、成本、摘要和电子发票选择。选择本次实际项目，核对自动回填的订单及业务部门；项目下拉找不到时用已验证的“空格→回车→空格→回车”加载方法，再查关键词并选择真实记录。

项目日常将科目与项目归属放在同一明细行；不要另造项目差旅专用的行程汇总或项目分拆步骤。实际表头还包含“附件”，根据本次上传入口及要求关联，不假定每个附件都必须重复上传到所有行。

### 普通日常的费用类型与部门

主表“报销费用类型”当前默认“部门费用”，另有行政费用、人资费用、品牌部费用、固定资产、成本费用、合约费用。默认值只说明页面初始状态；根据本次承担口径选择，不能只凭经办人的部门推定费用类型。

明细按“部门”归属，没有项目与订单字段。已看到“选择值”的部门选择入口；按当前表单展开并核对具体部门，不能把个人报销所在部门自动当成所有费用的承担部门。缺少必需的费用类型或部门时集中询问。

## 普通差旅

1. 使用 [项目差旅流程](travel-reimbursement.md) 中的票据提取、日期日历、差旅费用清单及汇总方法，但必须打开标题为“普通差旅报销”的表单。姓名、公司、报销部门仍按当前用户核对。
2. 先填写行程费用，再进入“费用分拆”。此处表头为“部门、费用、进项税、成本”，不查找项目或填写订单。按用户确认的承担部门分配；多部门时核对分配总和与报销金额。
3. 空白主表直接进入分拆曾提示“没有填写报销人或者报销金额”，因此先补齐已知主表及费用。不能为了绕过提示编造金额。
4. 按当前子表处理电子发票及专票字段；有电子发票登记要求则逐张登记。普通差旅的分拆子表完整行为尚未实测，需要取当前快照验证，不能声称其字段与项目差旅完全相同。

## 三类流程的收款、附件与交接

使用主表的收款信息及上传附件入口，按 [通用收款与附件操作](travel-reimbursement.md) 匹配本次收款人、核对银行回填、填写实付与冲账金额并上传对应原件及必要证明。收款信息来自当前用户或本次明确指示，不使用作者示例。

核对主表金额＝费用明细合计＝项目或部门分配合计；实付与冲账之和按本次应收口径核对。确认附件名称、数量、上传完成状态及所有已知必填字段。保存已核实的稳定个人资料，保留未提交页面，告知类型、用途、金额、收款人、附件及待补项，由用户本人检查并提交。
