# 报销表单共用操作

按本次类型读取对应流程，再在需要时使用本文。这里的控件方法不改变报销类型或费用归属。

## 票据与个人资料

- 按 [当前用户资料](user-profile.md) 核对报销人、报销所在部门、归属公司及收款人。费用承担部门、项目回填的业务部门与报销所在部门分别核对，不互相代替。
- 每次只处理指定出差或日常批次。明细账记录来源文件/页码、票种、票号、实际发生日期、开票日期、用途、含税金额、票面不含税金额及税额、拟报销金额、承担项目/部门及疑点。计算用十进制或整数分，保留两位小数。
- 发票、行程单、订单和付款记录可共同证明同一费用，只计一次。按票号等唯一信息去重；同金额不同票号不自动删除。折扣按折后价税合计，退款及部分报销单独核对。
- 票据通常不能证明商务目的或承担项目。餐饮票不能独立区分工作餐、业务招待或个人消费。购买方抬头与归属公司不一致时说明差异并询问本次口径；已有明确答复时不重复问。

## 定位、输入与核对

1. 财务入口是图片按钮，结合当前截图、DOM 图片和打开后的标题核对。不要只按第几个按钮点击；`/images/process/*.jpg` 只作为已观察的线索。
2. 同页有多个“新增”“修改”“确定”。按当前弹窗及相应费用、分拆、收款区域定位，查看邻近表头，不全页取第一个同名按钮。
3. 匿名下拉按钮从当前 DOM 的字段标题与相邻控件识别。动态 ID、ref、坐标不得写成长期定位。切换科目、电子发票“有/无”及打开子表后重新取快照；切换“有”会重新生成费用等输入框。
4. 替换已有文本：点击字段 → `Control+a` → `Backspace` → 输入 → `Tab`，查询记录最后按 `Enter`。普通 `fill` 曾把新内容接到旧内容上；空白金额框可以批量填写。核对最终值和自动计算结果。
5. 查询或菜单刚打开可能仍在异步加载，等待候选或新窗口出现。报“被覆盖”时先看最新页面，检查提示、加载遮罩或窗口切换，不盲点。选科目后查看新的报销选项，不复用旧选项。
6. 网格快照可能只有表头和空 `listitem`。从对应网格 DOM 的可见行文字核对；区分汇总行与明细行，不能重复求和。输出收款行时遮蔽完整银行账号。

## 部门级联菜单

普通日常的明细“部门”、普通差旅的“报销部门”子表使用此控件。

1. 点击“选择值”或已选部门名称按钮，打开组织菜单。
2. 对带子菜单箭头的上级组织使用 **hover/悬停**，等下一层菜单出现，再逐层移动到下级。2026-09-08 实测直接点击上级名称会选中该上级，不能用点击代替展开。
3. 根据本次已确认的承担部门及其层级选择真实记录。长菜单在当前菜单内滚动并重新读取候选，不把首屏当成全部部门，不因只看到公司根节点就选公司。
4. 点击最终部门后确认菜单关闭、按钮显示目标名称；主表明细行加入后再核对。带年份或同名记录需要区分，不确定则询问。示例账号的组织路径不作为其他用户默认值。

## 电子发票登记与进项税

日常报销在“新增/修改报销信息”内登记；普通差旅在“新增/修改报销部门”内登记；项目差旅在项目分拆内登记。此次核验的三类流程均已实际打开以下窗口并登记过电子普通发票。

1. 选择“是否有电子发票：有”，出现右侧“发票信息(进项税与电子发票)”，点击“新建”打开“新增发票信息”。**电子普通发票也选有**。项目日常实测选有但未登记就确认，会提示“请在右方面板添加电子发票”。
2. 打开“票类”下拉，选择与原件匹配的记录。当前见机票（扣除民航基金，税率 9）、高铁、汽车/船、普通发票(运输)、绿联、其它、电子发票等。初始高亮不代表正确票种；电子普通发票实测选择 **电子发票**。
3. 按原件填“票面金额(价税合计)”“发票号码”“发票数量”（逐张登记通常为 1），核对完整票号。普通电子发票实测扣除金额、税率、进项税额留空，所在费用行进项税为零。不能因交通费用就选带税率的机票或运输票种。
4. 点**发票子表的确定**，等待返回费用/部门/项目子表，核对发票行后录下一张。同一票号不在多个费用行重复全额登记；拆分报销先确认分配与登记口径。
5. 专票读取原件明确列出的不含税金额、税额与价税合计并核对相加关系。按已确认的适用口径填写进项税，不用普通票票面税额代替可抵扣额，不自行套税率；税务或部分报销口径不明时询问。
6. 核对费用、进项税和系统成本。日常表另有系统计算的“代扣偶然所得税金”，不随意覆盖。无进项税且代扣为零时实测成本等于费用；税额分拆不增加报销总额。专票及特殊代扣尚无真实实例验证。

登记票号、金额和上传文件是两个步骤，不能互相替代。

## 收款信息

先选公司并完成费用明细，使主表产生金额。项目日常空白表点击收款“新增”实测提示“没有填写归属公司或者报销金额”。另两类已在公司和金额齐全后成功添加收款行。

1. 在主表 **收款信息** 区域点“新增”，打开“新增收款信息”，选本次实际类型“个人”或“收款单位”。个人报销按当前账号资料匹配。
2. 在“收款方”输入姓名或单位关键词、回车并等待候选，必要时展开右侧下拉。个人候选有员工编号、姓名、部门，点击准确记录；不能只输入文字或停在高亮候选。
3. 核对系统回填的银行名称和账号，当前为只读字段。未回填时检查是否真正选中记录；同名多条或银行资料缺失时补问，不编造账号，不输出或保存完整账号。
4. 填“付款金额”和本次“冲账金额”。无冲账可填 0，有借款冲抵按本次确认值。申请金额应等于实付加冲账，多收款行核对合计。对外收款单位的银行付款备注按页面提示最多 17 个字。
5. 点**收款子表的确定**，核对主表收款行。三类流程已分别添加个人收款行并核对结果。

## 附件

三类主表均已打开“上传附件 → 请上传附件”，确认原生单文件输入为 `input.gwt-FileUpload[type=file]`，默认隐藏。上传、进度及回到主表的完整链路已在项目差旅真实任务验证；本次三类核验没有重复上传文件。

1. 按本次明细账准备原件和必要行程/消费证明，在本次报销委托范围内上传，不混入其他批次。
2. 打开主表“上传附件”。若快照只有“选择文件”而无可上传 ref，核对窗口和实际输入，仅把已存在的文件输入显示为 `block` 并赋予可访问名称，再取快照。将当前 ref 和本地绝对路径交给 BrowserOS Neo `upload`。
3. 每选一份即开始上传，并重新生成隐藏空输入；逐份重新定位，不复用上一份 ref，不向单文件输入塞多文件。
4. 核对以文件名标识的进度条都已到 `aria-valuenow=100`，点**上传窗口的确定**。回到主表核对名称、数量及“查看”链接。日常明细另有“附件”列，按实际关联入口和要求处理，不假定每行都要重复上传。

## 完成与交接

按对应类型核对金额、归属、日期/事项、税额、收款和附件。子表“确定”仅把记录加入当前主表，不能宣称已提交或已保存草稿。主表目前只见“提交/取消”，没有验证到独立草稿入口。

实际报销任务保留表单及标签页，保存经核实的稳定个人资料，告知本次类型、金额、收款、附件和待补项，由用户本人提交。不用“提交”测试校验。仅核验流程时使用独立临时表单，结束后取消该临时表单，不把探查选择保存为个人默认资料。
