# 霍普 ERP

将用户提供的差旅票据整理为可核对的报销表单，保留在 BrowserOS Neo 中，由用户本人检查并提交。

## 固定设置

- 网站：<https://erp.hyp-arch.com/#main>。该地址可能显示登录页，也可能显示已登录首页，以实际页面为准。
- 浏览器：BrowserOS Neo，使用其已有登录状态或浏览器自动填充。
- 票据邮箱：QQ 邮箱，入口 <https://mail.qq.com/>，使用 BrowserOS Neo 中已有的登录状态。
- 票据归档根目录：`D:\0-工作\发票`。发票、行程单、消费记录都归拢于此；每次出差放在一个独立子文件夹中。
- 财务入口：`my hyp → 我的财务 → 项目差旅报销`。
- 归属公司：`上海霍普建筑规划设计有限公司`。
- 收款人：`马腾宇`。如出现多个同名记录，结合当前用户已有信息核实。
- 完成方式：填好可确认的内容，核对金额和附件，提醒用户接手提交。保留当前表单；最终提交由用户本人操作。

## 连接与登录

1. 使用已安装的 `browseros-neo` 技能，先读它的 `SKILL.md`，按当前工具描述通过 BrowserOS Neo MCP 操作。尽早为会话命名；只操作本任务拥有的标签页。
2. 首次通过 `tabs` 的 `new` 操作打开上述网站。后续复用本任务的 ERP 标签页，避免重复创建、刷新或导航丢失已填内容。其他用户或代理拥有的标签页保留原状，按 BrowserOS Neo 技能的规则处理。
3. 已进入系统就继续；出现登录页且浏览器已填好账号密码时，直接点击页面上的“登录”。通过页面状态或脱敏截图判断自动填充是否就绪，不读取密码、Cookie 或浏览器凭据存储。
4. 若账号或密码未填、自动填充不可用或登录失败，提示用户在 BrowserOS Neo 页面内填写或检查，完成后告知，再继续。验证码等需要用户处理的步骤也保留页面交接。无需用户在聊天中提供密码。
5. 点击后核对页面已出现登录后的导航或首页内容，再进入业务流程。连接失败时按 BrowserOS Neo 技能排查，说明哪些页面尚未核实；不能声称已完成页面验证。

## 票据来源与归档

- 用户要求从邮箱找发票、补齐票据或归档时，读取 [QQ 邮箱取票与归档](references/qq-invoices.md)。先按本次出差或明确指定的邮件范围检索，再下载、核对并归入根目录下对应的出差子文件夹。
- 用户提供已有出差文件夹时直接读取。仅提供上述根目录时，先列出子文件夹，根据本次日期、地点或用户指示确定目标；不能把根目录下的全部历史票据合并为一次报销。
- 同一趟出差优先复用已有文件夹，新建时用实际出差日期和地点命名。同城不同日期的出差分别归档，不能仅凭城市或邮件收到日期合并。
- 每次报销的工作单元仍是一个出差文件夹。先确认文件可读并列出数量；没有明确出差范围时集中询问缺少的日期或地点，无需重复询问已知根目录。

## 项目差旅报销

执行时读取 [项目差旅报销流程](references/travel-reimbursement.md)，按证据提取、去重、归类、填表及核对的顺序完成工作。仅处理本次已确定的出差文件夹及其相关子目录。用户只要求邮箱取票或归档时，完成资料整理即可；要求办理报销时才继续填写 ERP。

在已授权的报销任务范围内继续填写已知内容，不为每一步重复请求确认。公司、收款人采用上述固定设置；项目、出差目的、税额及银行信息以用户资料或 ERP 现有记录为准。遇到必填且无法确定的事项，集中询问，同时继续可独立完成的整理工作。

只将可复用的入口、字段含义和操作方法沉淀回 skill。票据原件、账号凭据、完整银行账号和单次报销的个人明细保留在当次任务资料中。

## 流程维护与覆盖范围

当前实现 QQ 邮箱票据检索与 PDF 取票、出差文件夹归档、ERP 登录与项目差旅报销。补打卡、请假等业务在用户示范或实际查看页面后，分别补充入口、字段与完成条件，再加入业务路由。

流程来源：用户于 2026-09-07 提供的操作说明及真实出差示例。已实测 BrowserOS Neo 登录后导航、主表与日期填写、费用清单、全部项目查找与选择、电子普通发票逐张登记、收款信息及附件上传，并核对主表汇总。专票分拆按用户要求及已观察的字段说明执行，尚无专票实例验证。主表目前仅见提交与取消，需保留未提交表单。具体字段和操作方式见参考文档。
