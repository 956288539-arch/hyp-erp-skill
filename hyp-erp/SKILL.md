# 霍普 ERP

将用户本次票据整理为所选类型的报销表单，保留在 BrowserOS Neo 中，由用户本人检查并提交。

## 通用入口与完成方式

- 网站：<https://erp.hyp-arch.com/#main>。该地址可能显示登录页，也可能显示已登录首页，以实际页面为准。
- 浏览器：BrowserOS Neo，使用其已有登录状态或浏览器自动填充。
- 票据邮箱：QQ 邮箱，入口 <https://mail.qq.com/>，使用 BrowserOS Neo 中已有的登录状态。
- 财务入口：`my hyp → 我的财务`，再按本次确认的报销类型选择表单。
- 姓名、归属公司、报销部门、收款人和票据目录采用当前用户资料，不在公共 skill 中预设。
- 完成方式：填好可确认的内容，核对金额和附件，提醒用户接手提交。保留当前表单；最终提交由用户本人操作。

## BrowserOS Neo 环境检查

首次执行邮箱或 ERP 网页操作前，检查 BrowserOS Neo 是否已安装、运行，以及当前会话能否调用其 MCP 工具。当前任务已验证可用时直接复用。工具未出现或连接失败，不等于浏览器未安装；旧名称 `BrowserClaw` 也可能是有效的 Neo 安装。

环境缺失或连接异常时，读取 [BrowserOS Neo 安装与连接](references/browseros-setup.md)。**确认未安装时，先询问用户是否同意安装 BrowserOS Neo 并配置 Codex 连接；收到明确同意后才下载、安装和部署。** 这是用户指定的安装规则，不能将报销或整理发票的请求视为安装授权。同一会话已有明确安装授权时继续执行，无需重复询问。

用户同意后，执行官方安装、启动、Codex MCP 连接、配套技能检查和实际页面验证，再继续原任务。已安装但未连接时优先启动并连接现有安装。用户拒绝或尚未答复时不安装，可继续独立的本地票据整理。

## 连接与登录

1. 使用已安装的 `browseros-neo` 技能，先读它的 `SKILL.md`，按当前工具描述通过 BrowserOS Neo MCP 操作。尽早为会话命名；只操作本任务拥有的标签页。
2. 首次通过 `tabs` 的 `new` 操作打开上述网站。后续复用本任务的 ERP 标签页，避免重复创建、刷新或导航丢失已填内容。其他用户或代理拥有的标签页保留原状，按 BrowserOS Neo 技能的规则处理。
3. 已进入系统就继续；出现登录页且浏览器已填好账号密码时，直接点击页面上的“登录”。通过页面状态或脱敏截图判断自动填充是否就绪，不读取密码、Cookie 或浏览器凭据存储。
4. 若账号或密码未填、自动填充不可用或登录失败，提示用户在 BrowserOS Neo 页面内填写或检查，完成后告知，再继续。验证码等需要用户处理的步骤也保留页面交接。无需用户在聊天中提供密码。
5. 点击后核对页面已出现登录后的导航或首页内容，再进入业务流程。连接失败时按安装与连接参考文档及 BrowserOS Neo 技能排查，说明哪些页面尚未核实；不能声称已完成页面验证。

## 当前用户资料与记忆

登录后读取 [用户资料与本机记忆](references/user-profile.md)，以 ERP 当前账号精确加载个人配置。首次办理时读取 ERP 已有姓名、报销部门及收款候选，只询问本次缺少或有冲突的内容；不要把示例作者的信息用到其他用户。

当前指示与 ERP 已核实信息用于校验历史配置。报销部门、费用承担部门及项目回填的业务部门分别核对。首次表单填完并核对后，将稳定资料保存到 skill 目录之外的本机配置并回读；以后匹配到同一账号就复用。用户要求长期修改或忘记资料时同步更新，单次代办及业务信息不成为个人默认值。

## 每次选择报销类型

办理报销前读取 [报销类型选择与用途](references/reimbursement-types.md)。用户本次已明确类型时直接采用；未说明时简要介绍四类用途，再询问本次类型。用户不确定时集中询问是否出差、费用归属项目还是部门，给出依据并确认。收到回答后自动进入对应表单，不再重复询问是否打开。

报销类型只对本次任务有效，不记成下次默认类型，也不因为票据是餐饮、机票或来自某个目录就默认走项目差旅报销。类型待确认期间可先整理资料；不创建假定类型的正式报销表单。

## 票据来源与归档

- 用户要求从邮箱找发票、补齐票据或归档时，读取 [QQ 邮箱取票与归档](references/qq-invoices.md)。先按本次业务或明确指定的邮件范围检索，再下载、核对并归入当前用户归档根目录下的对应子文件夹。
- 用户提供已有报销文件夹时直接读取。仅提供归档根目录时，先列出子文件夹，根据本次日期、地点、事项或用户指示确定目标；不能把全部历史票据合并为一次报销。根目录未知且需要新归档时询问，不把单次文件夹自动记为长期根目录。
- 同一趟出差优先复用已有文件夹，新建时用实际出差日期和地点命名。同城不同日期的出差分别归档，不能仅凭城市或邮件收到日期合并。
- 每次报销的工作单元是一次出差或明确的日常费用批次。先确认文件可读并列出数量；日常报销按实际发生日期和事项归档，不编造出差日期。无需重复询问当前用户已确认的根目录。

## 按类型填写与交接

项目差旅报销读取 [项目差旅报销流程](references/travel-reimbursement.md)；项目日常、普通日常和普通差旅读取 [其他报销表单](references/other-reimbursements.md)，按证据提取、去重、归类、填表及核对的顺序完成工作。仅处理本次确定的资料范围。用户只要求邮箱取票或归档时，完成资料整理即可；要求办理报销时才继续填写 ERP。

在已授权的报销任务范围内继续填写已知内容，不为每一步重复请求确认。公司、部门和收款人采用本次核对后的个人资料；项目、事由、税额及银行信息以本次用户资料或 ERP 现有记录为准。遇到必填且无法确定的事项，集中询问，同时继续可独立完成的整理工作。

完成时核对费用、分配、收款与附件，保留未提交表单供本人检查。已核实的稳定资料通过 `scripts/user_profile.py` 保存到本机；只将可复用的入口、字段含义和操作方法沉淀回公开 skill。

## 流程维护与覆盖范围

当前支持按账号保存个人资料、每次报销类型选择、QQ 邮箱取票与归档，并提供四类报销表单的操作指引。项目差旅已用真实票据验证至提交前；另外三类已查看实际入口、主表和相关字段，尚未用真实报销验证完整流程。补打卡、请假等业务在用户示范或实际查看页面后再补充。

流程来源：用户于 2026-09-07 提供的操作说明及真实出差示例。已实测 BrowserOS Neo 登录后导航、主表与日期填写、费用清单、全部项目查找与选择、电子普通发票逐张登记、收款信息及附件上传，并核对主表汇总。专票分拆按用户要求及已观察的字段说明执行，尚无专票实例验证。主表目前仅见提交与取消，需保留未提交表单。具体字段和操作方式见参考文档。
