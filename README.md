# 霍普 ERP 助手

通过 BrowserOS Neo 从 QQ 邮箱或本地文件夹整理票据，确认本次报销类型后填写霍普 ERP，完成后由用户本人检查并提交。按 ERP 账号在本机记住个人资料，供后续办理复用。

## 已支持的流程

- 登录与 `My HYP → 我的财务` 导航，并选择本次报销类型。
- 项目差旅、项目日常、普通日常、普通差旅的用途介绍与表单路由；未明确类型时先询问，不沿用上次类型。
- 首次填写后记住当前用户的姓名、公司、报销部门、收款偏好和归档目录；不同 ERP 账号分别保存。
- QQ 邮箱检索、PDF 附件下载与去重，按一次出差归档发票、行程单和消费记录。
- 票据去重、费用分类、出差日期与报销总额核对。
- 主表、差旅费用清单、项目归属、电子普通发票登记、收款信息和附件上传。
- 项目栏通过“空格 → 回车 → 空格 → 回车”展开全部项目，再按关键词查找。

当前版本 **2026.09.08**。普通日常、项目日常、普通差旅已分别在实际 ERP 临时表单验证费用/分拆、电子普通发票登记、个人收款行及主表金额，并打开各自附件窗口核对控件；核验表单均已取消，没有提交审批。普通差旅包含“系统自动生成部门分拆后，应修改该行”的实际操作。

项目差旅此前已用真实任务验证至提交前，包含实际附件上传；此次另外三类没有重复上传文件。专票及特殊代扣尚无真实实例验证，请假和补打卡待补充。

## 安装

1. 将本仓库的 `hyp-erp` 文件夹复制到 `~/.codex/skills/`。
2. 首次使用时，由助手从 ERP 读取你的账号及已回填信息，只询问本次缺少或有冲突的资料。公共包不预设作者的姓名、公司、部门、收款人和本地路径。个人记忆脚本使用 Python 3 标准库。
3. 首次网页操作会检查 BrowserOS Neo。未安装时，助手先询问；你明确同意后，它会从官方渠道下载、安装、配置 Codex 连接并验证页面可用。已安装时复用现有环境，连接异常先排查。拒绝安装或尚未答复时，仍可整理已有本地票据。

详细部署见 [BrowserOS Neo 安装与连接](hyp-erp/references/browseros-setup.md)。系统授权弹窗及网站密码、扫码、验证码由用户在本机界面完成。安装指引已核对官方来源，全新机器上的安装流程尚未实测。

详细操作见 [QQ 邮箱取票与归档](hyp-erp/references/qq-invoices.md) 及下方四类报销流程。

### 更新已安装的旧版

拉取本仓库最新版本，或重新下载 [最新仓库压缩包](https://github.com/956288539-arch/hyp-erp-skill/archive/refs/heads/master.zip)，用其中完整的 `hyp-erp` 文件夹覆盖原安装目录的同名技能。**需要一起更新 `references/`，只替换 SKILL.md 不够。** 自定义了 `$CODEX_HOME` 时使用对应的 `skills/hyp-erp/` 目录。

更新后在安装目录核对 `SKILL.md` 的 `metadata.version` 为 `2026.09.08`，并有 `references/ordinary-daily-reimbursement.md`、`project-daily-reimbursement.md`、`ordinary-travel-reimbursement.md` 和 `form-common.md`。让桌面 agent 重新加载更新后的技能；若旧会话仍沿用已读指引，重新开会话明确要求读取当前安装版本。已填 ERP 表单保留原页面。

个人资料保存在 skill 目录之外，更新技能文件不清空已记住的姓名、公司与收款偏好。

## 报销类型

| 类型与独立操作流程 | 用途 |
| --- | --- |
| [普通日常](hyp-erp/references/ordinary-daily-reimbursement.md) | 日常费用按部门和费用类型归属，明细选科目、选项、承担部门。 |
| [项目日常](hyp-erp/references/project-daily-reimbursement.md) | 项目相关非出差支出，例如招待甲方，明细选择科目、选项和项目。 |
| [普通差旅](hyp-erp/references/ordinary-travel-reimbursement.md) | 部门承担的出差，先填行程，再核对自动部门分拆并登记发票。 |
| [项目差旅](hyp-erp/references/travel-reimbursement.md) | 具体项目的出差，行程费用通过项目分拆归属。 |

普通两类用途根据实际 ERP 字段判断，仍需核对业务及公司要求。询问和路由见 [报销类型选择](hyp-erp/references/reimbursement-types.md)，控件、电子发票、收款及附件见 [表单共用操作](hyp-erp/references/form-common.md)。

## 个人资料记忆

表单填完并核对后，助手自动保存已确认的稳定资料；下次核实到同一 ERP 账号即可复用，只核对变化项。可以说“以后归档目录改为……”或“忘记我的收款偏好”来更新或删除。报销类型、项目、事由、金额和单次代办信息不记为个人默认值。

资料位于 `$CODEX_HOME/user-data/hyp-erp/profiles/`；未设置该变量时为 `~/.codex/user-data/hyp-erp/profiles/`。文件保存在本机，独立于 skill 和 GitHub 仓库，更新 skill 会保留。不会保存密码、Cookie、完整银行账号或证件号码。更多见 [用户资料与本机记忆](hyp-erp/references/user-profile.md)。

## 使用

在 Codex 中提供本次票据文件夹、类型与用途，例如：

```text
使用 $hyp-erp 帮我填写这次报销。
本次类型：普通日常报销。
发票文件夹：D:\发票\本次办公采购
用途：部门购买打印耗材。
承担部门：填写实际承担部门
报销费用类型：填写经确认的类型
填好后提醒我检查，由我提交。
```

其他类型可以直接说明：“项目日常，因某项目招待甲方，未出差”“普通差旅，由指定部门承担，出差目的为已确认的工作事项”“项目差旅，归属指定项目”，并提供对应票据。类型不确定时先让助手介绍并询问。一个文件夹代表一次出差或明确的日常费用批次。登录信息未自动填入时，由用户在 BrowserOS Neo 页面内填写。Skill 会核对费用及附件，并保留当前表单供本人提交。

也可以提供本次日期和事项，请它从经确认的 QQ 邮箱寻找相关票据。归档根目录使用你的本机个人配置；首次未知时询问，每次报销使用对应子文件夹。仅要求取票或归档时，到资料整理完成为止。

## 仓库内容

`hyp-erp/SKILL.md` 是技能入口，`agents/openai.yaml` 提供 Codex 展示信息，`references/` 记录类型选择、用户资料与页面流程，`scripts/user_profile.py` 管理本机个人配置。`tests/` 使用虚构账号和隔离目录验证保存、复用与账号隔离。

发票原件、银行账号、登录凭据与单次报销明细不随仓库发布。
